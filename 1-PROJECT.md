# Braintrailz Flint

**Owner:** Marc J. Greenberg.
**Updated:** November 22, 2026.
**State:** v0.1.0 source is public on GitHub under MIT. A local bundle is prepared separately; no versioned GitHub release or global installation is claimed. Independent effectiveness and host qualification remain open.

## 1. Purpose

Turn an initial idea or known need into an evidence-backed decision about the next investment, then a proportionate definition that another capable participant can use to continue the work.

You bring the idea as kindling; Flint tests whether it can catch. Catching a spark earns the next experiment, not a commitment to a complete product.

**Working descriptor:** Find out what's worth building.

The name fits Braintrailz's fire/trail vocabulary and is shorter than Firstlight. Kindling was rejected by Marc as an awkward standalone name. No trademark, domain or public repository availability clearance is claimed.

## 2. Relationship to Trailcard

[Trailcard](https://github.com/braintrailz/trailcard) remains the general-purpose contract for purpose, success, authority, judgment, action and evidence. Flint is a software/project-definition companion, not a replacement.

Trailcard governs the work. Flint helps determine what work is worth authorizing and defines its scope. Repack preserves what is learned. These roles are related, not interchangeable.

The current task is bounded by [TRAILCARD.md](TRAILCARD.md). Future assignments need the applicable card and actual runtime permissions. A skill is instruction, not technical enforcement.

## 3. What Flint produces

- A scoped pursuit decision: Proceed, Investigate, Rescope, Defer or Stop.
- A delivery envelope: time, scope, cost, quality, capacity, dependencies and maintenance.
- Five proportionate artifacts: project, terms, spec, plan and design.
- An explicitly authorized next slice and the evidence that will be accepted.
- A handoff that preserves original intent, decisions, unknowns and provenance.

The initial package is an agent skill, templates/reference material and a small mechanical validator. A plugin, hosted service or orchestration platform is not the initial product.

## 4. Non-goals

Flint does not automatically validate demand, invent a business case, guarantee project success, demand long documents for every task, generate architecture for its own sake or treat an implementation plan as execution authority.

It does not reject a product solely because another tool has the same features. Experience quality, complementary capabilities and continuity may justify a different surface.

## 6. Delivery envelope

**Scope delivered:** skill entrypoint, six templates, four references, Node validator, 32 offline tests, Node evaluation-case review, local packager and usage guidance. No runtime dependencies or installation. warp-code was not modified during implementation.

**Time:** no deadline or engineering-hour cap supplied. Marc owns these decisions before sustained implementation. Do not infer a release commitment from this session's elapsed time.

**Cost:** no new paid services authorized. Existing model/agent usage may consume credits; actual dollar cost and a ceiling are unknown. Record available usage rather than reporting it as zero.

**Quality:** original intent and authority are preserved; evidence is inspectable; relevant NFRs are measurable or explicitly unresolved. No fabricated capability or passing result.

**Capacity:** Marc is product owner and reviewer. Available review time and recurring maintenance capacity are unknown and must be set before a delivery commitment.

**Tradeoffs:** reduce document detail or scope before silently lowering safety, privacy, correctness or evidence integrity.

## 7. Milestones

- **M0 — Defined:** six linked draft documents exist and actual checks are reported.
- **M1 — Usable skill:** a fresh agent can apply the method through Trailcard without this conversation.
- **M2 — Validator:** positive and negative synthetic checks demonstrate the limited mechanical contract.
- **M3 — Evaluated:** reviewed with-skill/baseline cases and a fresh-reader handoff reveal strengths and failures.
- **M4 — Reusable package:** Marc accepts the content, dependency model and distribution terms.

M0 is recorded. M1's package is implemented but its independent fresh-reader acceptance remains open. M2's mechanical checks pass. M3/M4 remain open. No milestone is accepted merely because an agent says it is done.
