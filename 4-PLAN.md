# Flint build plan
**Updated:** November 19, 2026. **State:** v0.1.0 implemented locally in JavaScript/Node; 32 mechanical tests pass. Human/model evaluation, host qualification, public licensing and publication remain open.
## Problem and current state
Package Marc's research-first, documentation-only project scaffold as a portable companion to Trailcard. Flint evaluates whether and how an idea merits a build; Trailcard governs authority, bounded judgment and evidence. The accepted working name is Flint, not Kindling or Firstlight. No public name or trademark clearance is claimed.
Marc authorized Flint v0.1 implementation and then required all tooling to use Node, with his language preference persisted for future sessions. The entrypoint, six templates, four references, Node validator, 32 offline tests, proposed eval cases, Node case-review tool and local archive builder now exist. warp-code was not modified during implementation and remains a development case, not an independent benchmark.
## F0 — Record the method and scope
**Recorded:** The six definitions exist and preserve the original intent, naming, Trailcard dependency, delivery envelope and evidence limits. The definition pass preceded the implementation authority now captured in `TRAILCARD.md`.
**Exit:** Definition structure/link checks passed. This does not establish skill effectiveness.
## F1 — Package the first skill
**Implementation authorized and built:** Marc's instruction to implement v0.1 authorized this slice; the follow-up selected JavaScript/Node. The package uses the existing Trailcard contract without bundling its implementation. Independent fresh-reader and human acceptance remain outstanding.
Create `skills/flint/SKILL.md`, proportionate five-document templates, a delivery-envelope guide, pursuit rubric and concise use guidance. Resolve Trailcard through the host's skill discovery or a user-supplied location; do not hard-code Marc's home directory, auto-install it or silently substitute a copied governance model. A supplied card may be reviewed; absent Trailcard/card, stop before governed work and explain what is needed.
The method captures verbatim intent, separates facts/assumptions/proposals, considers alternatives and weighs experiential and complementary value as well as feature parity. Outcomes are Proceed, Investigate, Rescope, Defer or Stop, always scoped to the next investment. Include compact treatment for small projects and decision-first treatment for uncertain ones.
**Exit:** A fresh agent can identify the trigger, prerequisites, outputs, authority limits and next decision without this conversation. Human review approves the content; merely generating five files is not enough.
## F2 — Add mechanical validation
**Built and mechanically tested:** Node 22+ target, ES modules and built-ins only. `npm run check` passes 32 tests on Node v26.3.0/macOS. `npm run validate` passes with one intentional outside-root-source warning. The local `.skill` archive passes an independent `unzip -t` integrity check and an extracted-validator relocation test. No Python runtime, third-party dependency or system ZIP executable is required by the implementation. Mechanical checks do not assess semantic traceability, project viability or factual accuracy.
**Exit:** Documented local test command passes both acceptance and rejection cases. Report exactly what the validator does not establish. No global installation, repository publication or new paid service.
## F3 — Evaluate before claiming effectiveness
**Prepared, not run:** Four cases are in `evals/evals.json`. `npm run evals` validates and displays them using Node only; it does not call a model, grade outputs or create scores. With-skill/baseline runs and a fresh-reader study require approval of prompts and budget. No Python-based evaluation tooling is part of this release.
Assess correct pursuit decisions, original-intent preservation, authority compliance, relevant measurable NFRs, proportionate output and fresh-reader continuity. Measure elapsed time, agent usage where available and human review burden; do not invent cost or savings.
**Exit:** Evidence and human feedback support a revision or acceptance; no benchmark score is claimed without a run. Model disagreement is a prompt to inspect ambiguity, not proof that every differing approach is wrong.
## F4 — Apply and refine through warp-code
The current implementation request narrowed work to Flint. No child agents launched and warp-code was not modified. Any future parallel work needs named assignments and review; the earlier two-child configuration is not authority to launch it.
warp-code tests whether the method distinguishes experience, complementary capabilities and session continuity from terminal feature parity. No build, bridge, supported wrapper, defer or stop are legitimate recommendations. Preserve the distinction between applying the method during its development and an independent effectiveness evaluation.
**Exit:** A source-linked case record identifies what Flint clarified, where the method needed correction and what remains unknown. Sanitize any redistributable example.
## Implementation record
Completed directly in the Flint tree, without delegation, provider calls, global installation, commits or publication. Language preference saved in the shared user rules and Claude/Codex user instruction files. The distributable contains only 12 allowlisted skill resources; private working cards, root definitions, evaluation prompts and tests are excluded.
## Delivery and quality gates
Deadline, engineering-hour budget, compute-credit ceiling and acceptable review time remain Marc-owned decisions before sustained implementation. Existing tools or agents are not described as free. Safety/privacy, authority preservation and truthful evidence are non-negotiable floors; scope and presentation detail can be negotiated.
Each relevant NFR records a target or explicit unknown, measurement, owner and gate. Cover security/privacy, correctness, performance/capacity, accessibility, compatibility, reliability/recovery, maintainability/operations and cost. A non-applicable category needs a reason. No arbitrary numeric target is imposed without rationale.
